## 0. Роль и цель

Ты — ведущий Python-разработчик исследовательского ПО для нейроинтерфейсов. Создай **работающий прототип** программной системы ЭЭГ-спеллера с интегрированной большой языковой моделью (БЯМ) по схеме **«Архитектура v3»**.

Приложенные входные файлы:
- `input/TZ.md` — техническое задание (идентификаторы требований NEED-F, NEED-M, REQ, VER-EXP);
- `input/architecture_v3.mmd` — схема «Архитектура v3» в Mermaid;
- `docs/*.md` — четыре проектных документа (ниже);
- `data/tasks_ru.txt` — задания для набора (формат описан в заголовке файла).

Проектные решения уже приняты и описаны в четырёх документах `docs/`. **Они — источник истины.** Твоя задача — реализовать их в коде, а не принимать заново:
- `ARCHITECTURE.md` — блоки, модули, контракты между блоками (раздел 4), цикл эпохи, режимы работы, структура пакета;
- `ASSUMPTIONS.md` — математические допущения MA-01…MA-33 с формулами и значениями по умолчанию, реестр экспериментов EXP-01…EXP-08;
- `OPEN_QUESTIONS.md` — открытые вопросы Q-01…Q-33 и временные решения по ним;
- `DATA_MODEL.md` — структура хранения, каталог событий, производные таблицы, экспорт.

Если документы противоречат друг другу или чего-то не хватает, не останавливайся: выбери разумный вариант, реализуй, промаркируй и **допиши** в соответствующий документ новую запись со следующим свободным ID (не меняя существующие ID).

## 2. Что реализовать и чего не делать

**Реализовать полностью** (по ARCHITECTURE, разделы 3–5): Primary Text; Source Model (Fast LLM) с mock-бэкендом MA-10 и маргинализацией MA-09 для токенных моделей; Symbol Distribution; Statistical Inference с двумя стратегиями слияния MA-12 и режимом «без БЯМ» MA-13; Primary Symbol Detector с режимами `label`/`abstain` MA-14 и флагом холодного старта MA-15; отправку обратной связи Top-K MA-16; Post-factum Text Correction с планировщиком MA-19, mock MA-18 и валидацией MA-20; Secondary Text; Session Recorder и Storage строго по DATA_MODEL; export и replay.

**Только заглушки:**
- **Physiology Module.** Никакой обработки ЭЭГ, фильтров, классификаторов. Только контракт `PhysiologyModule` (ARCHITECTURE, раздел 4), реестр плагинов и плагин `simulated`, который генерирует распределения по модели MA-04–MA-06 и временной модели MA-07. Плагин `stub_live` — пустая заготовка, бросающая `NotImplementedError` с отсылкой к Q-01. Приём обратной связи и RL-обновлений — только запись события.
- **Direct/Indirect RL.** Построение псевдометок MA-21 и рассылка во все связанные блоки; получатели только записывают. Калибровка MA-22 — реализовать как опцию `rl.mode: calibrate_offline`, выключенную по умолчанию и работающую только в replay.
- **Точки расширения вне v3** (ARCHITECTURE, раздел 8) — интерфейс и простейшая реализация.

**Не делать:**
- модуль динамической остановки эпохи (Q-05) — только `EpochPolicy` с единственной реализацией `FixedRepetitions`;
- дообучение моделей физиологии и БЯМ;
- полусинтетический режим (Q-02) — только место в реестре плагинов;
- сетевые вызовы по умолчанию (`llm.allow_remote: false`, Q-33).

## 3. Языковые модели как экспериментальный параметр

Выбор быстрой и медленной БЯМ — часть эксперимента (MA-08, MA-17, EXP-01, EXP-02). Поэтому:
- модель выбирается только через конфиг; код не должен предполагать конкретную модель;
- для каждого бэкенда в запись попадают `model_id`, версия, хеш весов или промпта и латентность каждого вызова (DATA_MODEL);
- бэкенды: `mock_ngram` и `mock_correction` (по умолчанию, без сети и GPU); `hf_causal` (локальная модель через `transformers`, ленивый импорт); `openai_compat` (только для медленной модели и только при `allow_remote: true`);
- быстрая модель требует полного распределения следующего токена; бэкенд, который его не даёт, должен явно отказываться работать в роли быстрой модели;
- реализуй `python -m eeg_speller bench-llm --config configs/exp01.yaml`: считает для быстрых моделей bits-per-char, средний `log p(целевой символ)`, Top-N точность слов и латентность p95 на `data/tasks_ru.txt` — это заготовка EXP-01.

## 4. Оценка и метрики

Все метрики и статистика — строго по ASSUMPTIONS, раздел I (MA-23…MA-32), с общим правилом нормализации текста. Модуль `evaluation/` работает только по записанным сессиям (`events.jsonl` и таблицы), а не по состоянию в памяти.

Команды:
- `python -m eeg_speller experiment --config configs/compare_llm.yaml` — N симулированных участников (по умолчанию 10) в режимах с БЯМ и без БЯМ по парному плану Q-26; сводная таблица с средним, дисперсией, 95 % ДИ и проверкой порогов в двух вариантах (MA-31);
- `configs/` содержит заготовки для EXP-03, EXP-04, EXP-05 (переборы параметров).

В выводе и в `REPORT_NOTES.md` явно указать: результаты получены на симуляции и не являются проверкой требований ТЗ.

## 9. Критерии готовности

- `pytest` проходит; все команды работают без сети и GPU.
- Два запуска с одинаковым сидом и одинаковым конфигом дают одинаковые `events.jsonl` после исключения полей, зависящих от реального времени запуска: `session_id`, `started_utc`, `ended_utc` и всех полей `wall_*`. Для этого в режимах `simulate` и `replay` поле `t_ns` берётся только из виртуальных часов.
- Replay сессии с тем же конфигом воспроизводит те же решения детектора.
- Экспорт проходит проверку полноты (DATA_MODEL, раздел 9).
- Смена физиологического плагина, бэкенда БЯМ, стратегии слияния, режима детектора и триггера коррекции — только через конфиг.
- Тест проверяет: при `mode.llm: off` prior равномерный, коррекция и кандидаты слов отключены.
- `check_markers.py` без расхождений; каждый MA и Q из документов встречается в коде хотя бы один раз или помечен в документе как «не реализуется в прототипе».
- `TRACEABILITY.md` покрывает все NEED-F и REQ.

# Физиологический модуль: EDF, LSL и контракт

Браузерный контроллер передаёт модулю порядок вспышек и измеренные времена их появления. Модуль принимает ЭЭГ, выбирает каналы, выделяет окна сигнала, обрабатывает их и возвращает правдоподобие каждого символа. Фраза задания и языковой prior модулю не передаются. Клавиатурная демонстрация реализует тот же интерфейс.

## Быстрая проверка без оборудования (Windows, PowerShell или cmd)

Из папки проекта после обычной установки:

```powershell
uv pip install -e ".[test,eeg]"
uv run --no-sync python -m eeg_speller.physiology.edf_demo --text "привет"
uv run --no-sync python -m eeg_speller.web.server --port 8767
```

Откройте `http://127.0.0.1:8767/operator` и `http://127.0.0.1:8767/`. В окне оператора выберите профиль **gui_edf.yaml**, задание **Свободный набор, без цели** и нажмите **Начать сессию**. Оставьте окно участника видимым. Пробел не нужен: после каждой эпохи появляется символ, декодированный из EDF. В конце файла сессия заканчивается автоматически. Профиль использует две серии вспышек с интервалом 500 мс: около 13 секунд на символ. Это демонстрационный темп, а не измерение скорости человека.

Замените `--text` любой строкой из алфавита спеллера, включая пробелы и знаки `. ,`. Генератор создаёт новую тестовую волну и независимую обучающую запись. `--seed` меняет шум тестовой записи. После генерации новую сессию можно запустить без перезапуска сервера.

Файлы в `runs/edf_demo/`:

| Файл | Назначение |
|---|---|
| `calibration.edf` | Отдельный синтетический сигнал для обучения |
| `calibration_labels.json` | Известные классы обучающих вспышек |
| `p300_model.json` | Обученные веса и параметры обработки |
| `test.edf` | Восемь каналов при 256 Гц и метки стимулов; содержит тестовый сигнал |
| `expected_test_only.json` | Ожидаемый результат для проверки человеком; приложение этот файл не читает |

Синтетический сигнал содержит шум, колебания, дрейф и вызванные ответы. Он служит для проверки программной интеграции. Точность на этом сигнале не доказывает точность на человеке. В режиме EDF внимание человека во время воспроизведения не меняет файл; для текущего внимания нужен живой EEG-поток.

## Контракт

Типы и протоколы находятся в `eeg_speller/physiology/base.py`.

| Направление | Сообщение | Содержание |
|---|---|---|
| Спеллер → физиология | `EpochStart` | ID эпохи, позиция, репертуар, парадигма, параметры и план вспышек |
| Спеллер → физиология | `StimulusEvent` | ID эпохи/вспышки, оценка фактического начала кадра в монотонных часах сервера, неопределённость времени |
| Физиология → спеллер | `PhysiologyObservation` | Нормированные логарифмические правдоподобия по всем символам, качество и диагностические оценки вспышек |
| Физиология → интерфейс | `status()` | Источник, соединение, каналы, частота, обработанные/отброшенные окна, качество синхронизации |

`InteractivePhysiologyModule` определяет запуск эпохи, получение плана, передачу событий, предварительную и окончательную оценку, завершение предъявления, проверку окончания источника и закрытие. Обратная связь/обновления сохранены для совместимости; онлайн-обучение по решению самого декодера не выполняется.

Контроллер проверяет ID эпохи, длину вектора, конечность и нормировку значений. Допускается только `semantics="likelihood"`: включение языкового prior внутрь физиологии привело бы к его повторному учёту при слиянии. Текст задания используется контроллером для оценки результата и отображения, а не для выбора целевой строки/столбца.

`EEGSource` в `sources.py` определяет транспортный слой: данные в вольтах, реальные времена отсчётов, получение окна по времени, статус и закрытие. `P300Physiology` и `P300Features` используют одинаковый декодер для EDF и LSL. Для устройств с готовым LSL-выходом код интерфейса и декодера менять не требуется. Для устройства с собственным SDK нужен мост в LSL либо отдельный адаптер `EEGSource`.

## Что происходит с сигналом

Из каждого стимула выделяется окно −200…800 мс. После проверки амплитуды выполняется фильтрация 0,5–15 Гц, затем для каждого выбранного канала вычисляется средняя амплитуда 250…500 мс относительно среднего предшествующего фона. Все параметры находятся в YAML. Обученный на калибровке небольшой Gaussian LDA даёт отношение правдоподобий «целевая / нецелевая вспышка». Эти оценки суммируются по символам, входящим во вспыхнувшую группу. Модуль поэтому поддерживает строки/столбцы и отдельные символы.

Обработка требует полного окна после вспышки: последнее решение появляется после поступления последних 800 мс сигнала. В EDF эти данные становятся доступными по времени воспроизведения; в LSL модуль ждёт соответствующие отсчёты. Окна с чрезмерной амплитудой исключаются. Если для какой-либо группы вообще нет пригодной оценки, модуль запрещает выбор символа. Также нужна хотя бы одна положительная оценка целевой реакции для каждого вида групп: для строки и столбца либо для отдельного символа. При её отсутствии один языковой prior не может вызвать ввод. Пропущенные/повторные маркеры, разрыв времени отсчётов и таймаут приводят к явной ошибке.

## Синхронизация

Перед каждой эпохой браузер делает пять коротких запросов времени. Из запроса с минимальным временем обхода оцениваются смещение `performance.now()` относительно монотонных часов Python и неопределённость как половина времени обхода. Вспышка задаётся в `requestAnimationFrame`; её временная метка переводится в часы сервера. Маркеры отправляются последовательно, не задерживая анимацию; все подтверждения проверяются перед декодированием.

В EDF времена аннотаций задают записанную шкалу. Первый браузерный кадр привязывается к первому записанному стимулу эпохи. Последующие кадры предъявляются по абсолютным относительным временам, и измеряется расхождение с записью. При превышении `max_replay_drift_ms` эпоха отклоняется. Сигнал для классификации берётся по исходным EDF-аннотациям. Это синхронное воспроизведение записанного опыта; никакие отсчёты не подменяются значением фразы из интерфейса.

В LSL временные метки отсчётов переводятся в локальные часы LSL через `time_correction()`. Монотонные часы Python привязываются к `local_clock()` локальным измерением. Поэтому события браузера и EEG-окна сравниваются в одной временной области. Физиология также публикует LSL-поток `SpellerStimuli` с исходным временем события для внешнего рекордера.

Время `requestAnimationFrame` — оценка кадра, не аппаратная метка свечения монитора. Половина времени обхода — программная оценка неопределённости, не гарантированная физическая точность. Для настоящего EEG-эксперимента нужны проверка задержки экрана/усилителя и, при наличии, фотодиод или аппаратные триггеры. Допустимые пороги задаются конфигом.

## Новое устройство: что поменять в конфиге

Скопируйте `gui_lsl.yaml` в свой `gui_<имя>.yaml`. Например:

```yaml
inherits: gui_edf.yaml
physiology:
  plugin: p300
  channels: [Cz, Pz, P3, P4]
  model_path: runs/my_device/p300_model.json
  source:
    kind: lsl
    stream_field: source_id
    stream_value: my-eeg-device
    units: uV
    channel_aliases:
      Cz: EEG-Cz
      Pz: EEG-Pz
      P3: EEG-P3
      P4: EEG-P4
```

Частота определяется из метаданных устройства. Если LSL-поток не содержит названий каналов, задайте `source.channel_order` в порядке столбцов потока. Единицы задаются явно в `source.units`. Изменение схемы электродов или обработки требует новой калибровки; переименование каналов через aliases сохраняет канонические имена модели.

Установка LSL:

```powershell
uv pip install -e ".[eeg,lsl]"
```

На платформах, где пакет не содержит liblsl, библиотеку нужно установить по [официальной инструкции LSL](https://labstreaminglayer.readthedocs.io/info/getting_started.html). Для реального устройства нужен его драйвер/мост, публикующий поток.

Калибровка по размеченной записи:

```powershell
uv run --no-sync python -m eeg_speller.physiology.calibrate --profile configs/gui_my_device.yaml --edf runs/my_device/calibration.edf --labels runs/my_device/calibration_labels.json --output runs/my_device/p300_model.json
```

EDF должен содержать аннотации `speller/<epoch_id>/<flash_id>/<kind>/<index>/<repetition>`; `kind` — `row`, `column` или `symbol`. JSON с обучающими метками — список объектов `{"epoch_id":0,"flash_id":0,"is_target":true}`. Обычный EDF без информации о предъявленных стимулах недостаточен для P300-декодирования. Записи с другой системой меток требуют преобразования этих меток. Тестовые ответы в этот файл обучения включать нельзя.

## Запись и изоляция

В каталоге каждой сессии сохраняются события начала кадров, синхронизация часов, оценки физиологии и решения. В `external/physiology/` копируются модель и исходный EDF. Для живого LSL сохраняются `lsl_eeg.npz` с выбранными каналами в вольтах и исходными исправленными временными метками; события стимулов лежат в `events.jsonl`. Хеши включаются в обычные контрольные суммы сессии. При ошибке сессия закрывается со статусом `failed` и событием `epoch_aborted`.

Для разработки на macOS добавлен отдельный запуск:

```sh
uv run --no-sync python scripts/run_local_sandbox.py --port 8767
```

Он использует macOS sandbox: содержимое домашней папки вне проекта закрыто, запись разрешена только в `runs/` и `configs/`, сеть разрешена только на localhost. Системные чтения доступны Python. Для EDF этого достаточно. Подключение физического LSL-устройства с другого компьютера потребует отдельного явно настроенного сетевого доступа. Обычный запуск через uv изолирует зависимости в `.venv`, но сам по себе не является системной песочницей.

Проверка кода с локальным LSL (PowerShell):

```powershell
$env:LSLAPICFG = "tests/lsl_local.cfg"
uv run --no-sync python -m pytest -q
```

LSL-тест пропускается, если опциональный pylsl не установлен. Локальная конфигурация ограничивает обнаружение текущим компьютером; для настоящей аппаратуры используйте отдельную конфигурацию сети. [Настройки LSL](https://labstreaminglayer.readthedocs.io/info/lslapicfg.html)
